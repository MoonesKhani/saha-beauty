# سالن زیبایی سها

لندینگ فارسی و راست‌به‌چپ سها؛ اطلاعات سالن، خدمات و مسیرهای تماس در قالب موجود حفظ شده‌اند.

## اجرای محلی

از ریشه مخزن اجرا کنید:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

نصب بسته یا ساخت جداگانه لازم نیست. محیط به دسترسی به شبکه توزیع محتوای کتابخانه‌های موجود نیاز دارد.

## ساختار

- `index.html`: خروجی بسته‌بندی‌شده شامل قالب، فونت‌های موجود و منطق تعامل‌های صفحه؛ داده قالب در برچسب `__bundler/template` به‌صورت رشته JSON است. هنگام ویرایش، اعتبار JSON و رفتار بارگذار باید حفظ شود.
- `assets/saha-premium.css`: رنگ‌ها، تایپوگرافی، ترکیب‌بندی واکنش‌گرا، کارت‌ها و دکمه‌های منتخب شیشه‌ای.
- `assets/saha-premium.js`: شکوفه‌افشانی یک‌باره، حرکت اسکرولی، نمایش تدریجی و کنترل توقف حرکت؛ بدون کتابخانه جدید.
- `assets/saha-cinematic-hero*.webp`: تصویر تزئینی تولیدشده و بهینه‌شده برای موبایل و دسکتاپ؛ این تصویر، نمونه‌کار واقعی سالن نیست.
- `assets/saha-blossoms.svg`: تصویرسازی اختصاصی گل و بافت پیوسته زمینه.

نظر مشتری، مدرک، قیمت و نمونه‌کار واقعی جدیدی ساخته نشده است؛ جایگاه‌های موجود با توضیح مشخص نگهداری شده‌اند. راهنمای انتخاب رنگ نیز بر پایه گزینه‌های موجود است و تشخیص یا تحلیل هوش مصنوعی نیست.

پیش از انتشار، موبایل و دسکتاپ، کاهش حرکت، کنترل صفحه‌کلید، مسیر رزرو و تماس، پسندها، پکیج‌ها، رنگ‌ها و شکل‌گیری گلبرگ‌ها بررسی شوند. تنظیمات دامنه و فایل `CNAME` بخشی از بازطراحی نیستند.

## آزمون رفتاری

با وجود بسته توسعه `playwright` و مرورگر Chromium، سرور محلی را اجرا کرده و در ترمینال دوم بزنید:

```sh
python3 tests/smoke_test.py
```

نشانی سرور با متغیر `SAHA_TEST_URL` و مسیر مرورگر با `SAHA_CHROMIUM` قابل تغییر است. آزمون چهار اندازه صفحه، بارگذاری تصویر، انیمیشن یک‌باره، توقف حرکت، تمام بخش‌های خدمات، پکیج‌ها، پسندهای ذخیره‌شده، راهنمای رنگ، تماس، صفحه‌کلید و کاهش حرکت را بررسی می‌کند. گزارش و تصویرهای موقت در `/tmp` ذخیره می‌شوند.

## بک‌اند و رزرو واقعی

بک‌اند FastAPI و PostgreSQL، برنامه متخصص‌ها، رزرو تراکنشی و مدیریت دارای احراز هویت در پروژه قرار دارند. پرداخت خاموش است و ظرفیت نمونه برای رزرو واقعی استفاده نمی‌شود. اجرای کد روی GitHub Pages کافی نیست؛ [راهنمای استقرار آروان](BACKEND-DEPLOY.md) را ببینید. وضعیت آماده‌بودن کد را از اجرای واقعی روی سرور جدا در نظر بگیرید.

## پکیج‌ها و مدیریت محتوای جدید

صفحه `bridal.html` پکیج‌های عروس، عقد و همراه را مقایسه می‌کند؛ `birthday.html` همان انتخاب و محاسبه خدمات را برای تولد دارد. قیمت‌ها تومان‌اند. قیمت نهایی برابر قیمت پایه پکیج، به‌علاوه تعرفه خدمات اضافه و منهای تعرفه خدمات حذف‌شده است. تا وقتی تعرفه لازم مشخص نشده باشد، قیمت نهایی و ثبت پکیج تأیید نمی‌شوند. قیمت پایه خالی (مانند تولد) یعنی جمع تعرفه خدمات انتخابی؛ خالی به معنی صفر نیست. خدمات همراه عروس باید ابتدا در پنل تعریف شوند.

برای اجرای نسخه جدید، از ریشه مخزن:

```sh
.venv/bin/python -m backend.app.cli init-db
.venv/bin/python frontend/build.py
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

`init-db` مهاجرت `0004_packages` را اجرا و داده اولیه را بدون بازنویسی ویرایش‌های مدیر اضافه می‌کند. پیش از ارتقای دیتابیس واقعی پشتیبان بگیرید. این فرمان‌ها برای توسعه‌اند و سایت عمومی را منتشر نمی‌کنند.

پنل `/admin` مدیریت پکیج‌ها و تصاویر گالری (نشانی تصویر محلی یا HTTPS، دسته و عضو تیم) را دارد. بخش «تخصص‌ها و برنامه کاری» تخصص هر فرد را مستقل از مدت خدمت و ساعات کاری ذخیره می‌کند؛ مدت یا ظرفیت پیش‌فرض ساخته نمی‌شود. ناخن، مانیکور، پدیکور و ژلیش فقط به کوثر عبدالخانی قابل تخصیص‌اند. دستیاران در پنل کارکنان با فیلد سرپرست مدیریت می‌شوند. تغییرات پنل با تازه‌سازی صفحه‌های سایت دیده می‌شوند. قیمت محاسبه‌شده هنگام رزرو در سرور نگهداری می‌شود.

تست‌های این توسعه:

```sh
.venv/bin/python -m pytest -q
.venv/bin/python tests/package_browser.py
```

تست دوم دیتابیس و کلید آزمایشی موقت خودش را می‌سازد و ویرایش پنل و نمایش عمومی را در موبایل و دسکتاپ بررسی می‌کند. Chromium سیستم و دسترسی مجاز به CDN کتابخانه‌های فعلی لازم است. انتشار عمومی و اتصال دامنه همچنان نیازمند تأیید مالک است.

### ویرایش زنده پنل و بارگذاری نمونه‌کار

در پنل واقعی، بخش «پکیج‌ها» امکان ویرایش توضیحات، قیمت پایه و خدمات هر پکیج را دارد. در «گالری تصاویر»، عنوان، دسته و متخصص را انتخاب و عکس JPG، PNG یا WebP را مستقیماً از دستگاه بارگذاری کنید؛ سپس «ذخیره» را بزنید. عکس فقط پس از ذخیره رکورد فعال گالری عمومی می‌شود. تصاویر از مسیر `/api/v1/gallery-media/` نمایش داده می‌شوند تا از مسیر API موجود عبور کنند. تصاویر با حذف فراداده و اندازه بهینه روی سرور ذخیره می‌شوند؛ آدرس دستی تصویر نیز همچنان قابل استفاده است.

تغییرات پنل با سیگنال همان مرورگر و بازخوانی حداکثر هر ۱۵ ثانیه در صفحه اصلی، پکیج‌ها، گالری و منو نمایش داده می‌شوند. نیازی به انتشار مجدد کد برای ویرایش محتوا نیست. دمو هیچ تغییری در سایت عمومی ایجاد نمی‌کند.

آپلود از مسیر `POST /api/v1/admin/gallery-upload` فقط با احراز هویت مدیر انجام می‌شود. فایل ورودی حداکثر ۱۰ مگابایت و ۲۰ میلیون پیکسل است. مسیر نگهداری پیش‌فرض `var/gallery` و سهمیه پیش‌فرض ۲۵۰ مگابایت است؛ با `SAHA_GALLERY_UPLOAD_DIR` و `SAHA_GALLERY_UPLOAD_QUOTA` قابل تنظیم‌اند. در Docker این مسیر داخل volume پایدار `uploads` است. هنگام پشتیبان‌گیری، این volume را علاوه بر PostgreSQL حفظ کنید.

اجرای این قابلیت‌ها در سایت عمومی به ارتقای بک‌اند نیاز دارد؛ GitHub Pages به‌تنهایی API یا فایل‌های بارگذاری‌شده را میزبانی نمی‌کند. پراکسی دامنه باید `/api/v1/*` و `/admin` را به همین بک‌اند برساند. بررسی آماده‌بودن برای پراکسی‌های مسیرمحور از `/api/v1/health/ready` نیز ممکن است.

### ارتقای بک‌اند موجود از Termius

در سروری که سرویس فعلی با Docker Compose پروژه `saha` اجرا می‌شود، `scripts/server-update.sh` پوشه همان استقرار را از Docker پیدا می‌کند؛ اگر مسیر متفاوت است آن را به‌عنوان آرگومان بدهید. اسکریپت در صورت نبود فایل `.env`، تغییر ذخیره‌نشده در مخزن یا نبود سرویس‌های موجود متوقف می‌شود. قبل از ارتقا، دیتابیس و volume فایل‌ها را در `backups/update-…` پشتیبان می‌گیرد؛ سپس فقط سرویس app را با حفظ داده‌ها و کلید مدیریت به‌روز می‌کند. تنظیمات دامنه و پراکسی را تغییر نمی‌دهد.

این اسکریپت روی سرور اصلی از این محیط اجرا نشده است؛ اتصال SSH محیط همچنان رد می‌شود، با اینکه کاربر اتصال Termius خود را تأیید کرده است.

بررسی تمیزبودن مخزن با `git status --porcelain=v1 --untracked-files=no` انجام می‌شود؛ فقط خروجی غیرخالی تغییر فایل‌های تحت کنترل Git محسوب می‌شود. خطای اجرای Git پیام جداگانه دارد. فایل‌های محلی و نادیده‌گرفته‌شده مانند `.env`، رزروها و آپلودها حذف نمی‌شوند.

برای دریافت نسخه جدید اسکریپت از Git و اجرای آن بدون ویرایش فایل داخل مخزن، در پوشه همان پروژه روی سرور اجرا کنید:

```sh
git fetch origin main &&
git show FETCH_HEAD:scripts/server-update.sh > /tmp/saha-update-fixed.sh &&
bash /tmp/saha-update-fixed.sh "$(git rev-parse --show-toplevel)"
```

دریافت کد با Git انجام می‌شود. اسکریپت از داده‌ها پشتیبان می‌گیرد و ارتقا را با حفظ `.env` و volumeهای موجود انجام می‌دهد؛ از `git reset --hard`، `git clean` یا `docker compose down -v` استفاده نکنید.

تست مستقل پیش‌شرط‌های اسکریپت، بدون تماس با سرور یا اجرای Docker واقعی:

```sh
.venv/bin/python -m unittest discover -s tests -p test_server_update.py -v
```
