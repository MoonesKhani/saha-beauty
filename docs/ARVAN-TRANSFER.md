# انتقال خصوصی بستهٔ انتشار از فضای ابری آروان

این تغییر فقط مسیر انتقال بسته را آماده می‌کند. هیچ انتشار، migration، تغییر
DNS، راه‌اندازی کانتینر یا پیامک واقعی در آماده‌سازی اجرا نمی‌شود. انتخاب مسیر
آروان به معنی تأیید سرعت واقعی نیست؛ آزمون دو مسیر زیر پس از تنظیم دسترسی لازم است:

1. GitHub runner → باکت خصوصی انتخاب‌شده در منطقهٔ داخل ایران.
2. باکت → گیرندهٔ محدود روی سرور، با کنترل کامل ZIP و release.tar.

## یک بار توسط مالک

1. در پنل آروان، فضای ابری / Object Storage، باکت جدید با نام دارای حروف کوچک،
   عدد و خط تیره بسازید؛ منطقهٔ داخل ایران و دسترسی خصوصی را انتخاب کنید. نام
   منطقه و Endpoint را دقیقاً از پنل بردارید، نه از مثال‌ها یا حدس. هزینهٔ سرویس
   تابع تعرفهٔ نمایش‌داده‌شدهٔ پنل است؛ خودکار باکتی ایجاد نمی‌شود.
2. فقط نام باکت، منطقه و Endpoint را در گفت‌وگو بدهید. کلید را در چت نفرستید.
3. کلید S3 جداگانه با حداقل دسترسی لازم بسازید. در صورت پشتیبانی پنل، دسترسی را
   به همین باکت و `saha-releases/` محدود کنید. PutObject، GetObject و برای مدیریت
   خطای multipart، AbortMultipartUpload لازم‌اند؛ حذف سایر اشیا یا ساخت باکت لازم نیست.
4. در GitHub → repository → Settings → Secrets and variables → Actions، دو
   **Repository Secret** ثبت شوند:
   - `ARVAN_STORAGE_ACCESS_KEY_ID`
   - `ARVAN_STORAGE_SECRET_ACCESS_KEY`
   کلیدهای SSH قبلی و کلید پیامک تغییر نمی‌کنند. Codex فعلی مجوز خواندن فهرست
   Secrets/Variables را ندارد (HTTP 403)؛ این به معنی نبودن آن‌ها نیست.
5. در تب Variables همین قسمت، مقادیر غیرمحرمانه ثبت شوند:
   - `ARVAN_STORAGE_ENDPOINT`: آدرس HTTPS دقیق، بدون نام باکت یا مسیر.
   - `ARVAN_STORAGE_BUCKET`: همان باکت خصوصی.
   - `ARVAN_STORAGE_REGION`: همان region پنل.
   - `ARVAN_STORAGE_PREFIX`: `saha-releases/`، اختیاری با همین پیش‌فرض.
6. پس از CI موفق، Codex دستور Termius با SHA دقیق برای `update-deploy-runtime.sh`
   و سپس `configure-arvan-transfer.py --endpoint ... --bucket ... --region ...`
   آماده می‌کند. اسکریپت دوم فقط `/opt/saha-deploy/arvan-transfer.json` را می‌نویسد
   و نسخهٔ قبلی همین فایل را خصوصی نگه می‌دارد؛ هیچ credential در آن نیست. ابزار
   نصب، `.env`/config اصلی/SSH keys/برنامه/دیتابیس/uploads را تغییر نمی‌دهد.
   دستور دقیق پس از دریافت اطلاعات واقعی آماده می‌شود؛ placeholder اجرا نشود.

## امنیت و رفتار انتقال

- همان ساخت و تست Docker روی GitHub و همان اسکریپت server-update/backup/health/
  image rollback باقی می‌مانند. schema guard و طرح جداگانه OTP تغییری ندارند.
- SDK رسمی boto3 فقط در venv موقت runner نصب می‌شود؛ روی سرور SDK و S3 Secret
  نصب/ذخیره نمی‌شود. SigV4، TLS معتبر و path-style برای سازگاری S3 فعال‌اند.
  checksum اختیاری جدید AWS که ممکن است با S3-compatible سازگار نباشد غیرفعال
  است؛ کنترل مستقل SHA-256 روی کل فایل همواره برقرار است.
- فایل ZIP سازگار با گیرندهٔ موجود، دو عضو ثابت release.tar و checksum دارد.
  object key شامل commit کامل و SHA-256 خود ZIP است. آپلود خصوصی، multipart
  هشت MiB با حداکثر دو worker و retry محدود SDK انجام می‌شود.
- قبل از آپلود، گیرنده باید hash همان endpoint/bucket/region/prefix را تأیید کند.
  اختلاف تنظیمات یا گیرندهٔ قدیمی باعث توقف پیش از آپلود و نصب می‌شود.
- گیرنده فقط میزبان دقیق و مسیر همان باکت/پوشه/commit/hash.zip را می‌پذیرد؛
  redirect، میزبان دلخواه، HTTP، userinfo یا خروج از مسیر مجاز نیست.
- لینک امضاشده ۱۰ دقیقه اعتبار دارد و فقط از stdin رمز‌شدهٔ SSH عبور می‌کند؛
  در argv، log یا state ذخیره نمی‌شود. پیام خطا مقادیر credential/URL را چاپ نمی‌کند.
- حجم و metadata آپلود بررسی می‌شوند؛ اثبات نهایی صحت، دانلود کامل و SHA-256
  مستقل ZIP و release.tar روی سرور است. فایل ناقص هیچ‌گاه نصب نمی‌شود.
- دریافت از offset تأییدشده ادامه می‌یابد؛ قبل از retry وضعیت فقط‌خواندنی گرفته و
  URL تازه ساخته می‌شود. staging حداکثر دو تلاش دارد؛ نصب نامشخص تکرار نمی‌شود.
- workflow جدید `arvan-transfer-check.yml` فقط dispatch دستی روی main است؛ نمونه
  حدود ۱۲۸ KiB غیرقابل‌نصب را آزمایش می‌کند. هیچ deploy/migrate/Pages اجرا نمی‌کند.
  نمونهٔ خصوصی در باکت می‌ماند و خودکار چیزی پاک نمی‌شود؛ retention بعداً تنظیم می‌شود.
- برای انتشار واقعی پس از موفقیت آزمون، SHA اصلی و CI موفق به مالک اعلام و تأیید
  نهایی مستقل گرفته می‌شود. deploy.yml مسیر Arvan را پیش‌فرض دارد، Azure فقط
  انتخاب صریح است؛ fallback پنهان به مسیر ناموفق انجام نمی‌شود.

## وضعیت فعلی

مالک هنوز باکت ندارد؛ endpoint/region/دسترسی واقعی موجود نیست. تست‌های آفلاین
محدودسازی مقصد، شکست آپلود، hash، ZIP سازگار، عدم شروع نصب و عدم افشای URL
با fixture بررسی می‌شوند. آزمون شبکهٔ واقعی تا ثبت اطلاعات و نصب allowlist انجام
نمی‌شود و پایداری هنوز ادعا نمی‌شود.
