# وضعیت پروژه سها

آخرین تأیید کاربر: انتشار همان نسخه پیش‌نمایش ۴، بدون تغییر بیشتر در طراحی؛ ادامه اصلاح طراحی در مرحله بعد.

## نسخه تأییدشده

- لندینگ فارسی، راست‌چین و واکنش‌گرا با حفظ هویت، رنگ‌ها و انیمیشن‌های موجود.
- منوی سه‌نقطه برای گالری، تخفیف نمایشی، مشاوره هوش مصنوعی آینده، دعوت از دوست، روزمره، مدارک و ترندها.
- نمایش اولیه سه خدمت اصلاح، پاکسازی و ناخن؛ بقیه با مشاهده همه خدمات. پکیج‌ها افقی و ورق‌زدنی‌اند.
- موسیقی به‌صورت آیکون گوشه صفحه و پیش‌فرض خاموش؛ ساعات کار بدون کادر.
- کارت‌های چرا سها، ارتباط و گفتگوی مدیر کوچک‌تر شده‌اند. خوشامد عربی با فونت ساده کنار منتظر دیدارت هستیم است.
- روزمره، مدارک و ترندها از صفحه اصلی خارج و مستقل شده‌اند. بخش چه تغییری بهت میاد حذف شده است.
- روزمره، مدارک و هوش مصنوعی برای توسعه آینده‌اند؛ محتوای واقعی، مدارک یا نمونه‌کار ساختگی اضافه نشود.
- نمونه‌کارها از فهرست داده بارگذاری می‌شوند. پسندها و قابلیت‌های نمایشی مرورگر، جایگزین خدمات واقعی سرور نیستند.

## ساختار و ادامه کار

- `index.html` قالب بسته‌بندی‌شده دارد؛ قالب داخلی رشته JSON در `__bundler/template` است. صفحه بازنویسی نشود.
- تغییرات جمع‌وجور موبایل در `assets/saha-mobile-v2.css` و تعامل‌های مرتبط در فایل‌های `saha-compact`، `saha-secondary` و `saha-trends` هستند.
- پس از تغییر فایل‌های مربوط، `python3 scripts/build_landing_assets.py` نام فایل‌های نسخه‌دار را با محتوایشان هماهنگ می‌کند.
- `python3 scripts/build_mobile_preview.py` پیش‌نمایش مستقل قابل دانلود برای بررسی قبل از انتشار می‌سازد.
- آزمون‌های مرورگر: `tests/mobile_compact_preview_test.py` و `tests/preview_secondary_test.py`؛ نشانی با `SAHA_TEST_URL` تنظیم می‌شود.
- فرانت‌اند ثابت از شاخه main در GitHub Pages منتشر می‌شود. بک‌اند FastAPI، PostgreSQL و کد مدیریت در مخزن موجودند؛ انتشار صفحات ثابت به معنی فعال‌بودن بک‌اند نیست.
- رزرو، پرداخت، آپلود، هوش مصنوعی و پنل مدیریت تنها پس از بررسی اتصال واقعی و احراز هویت آماده استفاده واقعی‌اند؛ پرداخت بدون درگاه معتبر فعال نشود.
- فایل CNAME، دامنه، تنظیمات سرور، دیتابیس و درگاه در این مرحله تغییر نکنند. هیچ کلید خصوصی در مخزن یا گزارش قرار نگیرد.
- ادامه طراحی روی نسخه منتشرشده با پیش‌نمایش و تأیید کاربر انجام شود.

## بررسی نسخه

آزمون مرورگر در اندازه‌های ۳۲۰، ۳۹۰، ۴۱۲ و ۱۴۴۰ پیکسل، صفحات مستقل، منو، تماس، چیدمان و پیش‌نمایش مستقل موفق بود. ۲۵ آزمون بک‌اند نیز موفق بود.

## اصلاح رزرو و تیم — آبان ۱۴۰۵

- کارت‌های خدمت به `booking.html?service=…` می‌روند و انتخاب خدمت همان گزینه قفل می‌شود. کارت کلی مو اجازه انتخاب تنها یکی از زیرخدمت‌های مو را می‌دهد.
- رزرو کامل برای هر خدمت یک متخصص و ساعت مستقل دارد. تنها تخصیص‌های تأییدشده سالن از کاتالوگ جدید برای انتخاب متخصص استفاده می‌شوند؛ تخصص فرضی ساخته نشود.
- API جدید `POST /api/v1/booking/reservations/batch` همه خدمت‌ها را در یک تراکنش ثبت می‌کند؛ تداخل زمان مشتری، اشغال ظرفیت و ارسال تکراری کنترل می‌شوند. رزرو تک‌خدمت با API قبلی سازگار است. پرداخت خاموش است.
- کاتالوگ جدید `batch_enabled` و `reviews_enabled` و `team[].service_codes` دارد. با بک‌اند قدیمی، ثبت چندخدمتی فعال نمی‌شود و موفقیت ساختگی نمایش داده نمی‌شود.
- زنگوله ترمیم برای ناخن، آرایش دائم و مژه صرفاً یادداشت محلی مرورگر است؛ هیچ پیامک، اعلان خودکار یا تاریخ ترمیم فرضی وجود ندارد.
- کارت‌های تیم کوچک‌تر و شرح تخصص و سابقه کنار تصویر قرار گرفته‌اند. عکس و نام به `team-member.html?member=…` وصل‌اند؛ صفحه برای تکمیل بعدی است.
- کادر تکراری خلاصه ارتباط در فوتر و توضیح تصویری پایین تیم حذف شده‌اند. مسیر مخفی پنج کلیک فوتر حفظ شده است.
- دکمه + نظرات فرم خصوصی باز می‌کند؛ `POST /api/v1/reviews` پیام را در جدول موجود consultations با موضوع «نظر مشتری» ذخیره می‌کند. مدیر از درخواست‌های مشاوره آن را می‌بیند؛ نظر خودکار عمومی نمی‌شود. شماره مشتری در فرانت‌اند یا فهرست عمومی ذخیره نمی‌شود.
- این تغییر مهاجرت دیتابیس یا تغییر احراز هویت ندارد. برای APIهای جدید باید بک‌اند آروان نیز با بکاپ قبلی و حفظ `.env` و volumeها به‌روزرسانی شود؛ انتشار GitHub Pages به‌تنهایی این کار را انجام نمی‌دهد.
- ۳۰ آزمون بک‌اند، آزمون مرورگر با دیتابیس موقت واقعی، مسیرهای قدیمی، نبود بک‌اند، سازگاری نسخه قدیمی و رگرسیون چیدمان و ورودی مخفی بررسی شده‌اند.
